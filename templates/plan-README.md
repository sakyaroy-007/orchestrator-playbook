## 7. 协作规程

**派发**：
1. 总指挥在 `status.md` 把卡标为「可派」。
2. 用 `scripts/wt.sh new <卡号> <slug>` 建 worktree。
3. 预检 `pwd` 和分支。
4. 把卡顶的派发口令原样发给执行者。
5. 执行者只在自己的 worktree 里干活，按 `WORKER.md` 的模板回报。

**审查**（总指挥不接受自报）：
1. 进 worktree 复跑验收。
2. 读完整 diff，查越界、假测试、密钥残留、不可逆操作。
3. 核对 `docs/changes/<卡号>.md`。
4. 通过：`--no-ff` 合入 {{MAIN}} → 跑全量测试 → 推送 → 同步文档 → `wt.sh rm`。
5. 不通过：写 `reviews/<卡号>-rN.md`，派回原执行者。
6. 总指挥自己写的卡，合并前另起一个独立审查，不让它看总指挥的结论。

**纪律**：
- 同一执行者在同一问题上失败两次，换人或换模型。
- 🔒 卡全局串行。
- 需要拍板的事进 `questions.md`。
