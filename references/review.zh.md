# 审查、验收与整合

员工的 `done` 或退出码 0 是回报，不是验收。按项目 `review` 策略和实际影响选择检查。[生命周期](lifecycle.zh.md)规定所有权，[派发](dispatch.zh.md)规定受管 verify/guard 命令。可回滚的文档修改不必一律全套测试或另起 agent 审查。

## 形成审查证据

1. 记录审查基线、当前 HEAD、分支/工作目录、配置 revision、dirty/未跟踪状态。分清已有改动和本卡补丁，不能为得到干净截图擦掉成果。
2. 读完整范围 diff 和变更说明，未授权提交时也包含未提交交付。每个“已更新”都与文件核对。
3. 对实际结果跑卡上相关验收，记录 cwd、退出状态、真实输出和覆盖范围。验收过时就解释，并在授权范围内调整，不能编造通过。只有共享行为或未决问题需要时扩大测试，遵守项目必要检查。
4. 共享状态、测试隔离或顺序依赖相关时，对受影响测试单跑、逆序/随机跑，不要求每次改动全套逆序。
5. 检查越界、绕过失败、削弱断言、照抄输出作期望、秘密残留和破坏性默认值。测试数量本身不证明覆盖。文档/调研卡需要准确结论和有效引用，不靠任意小节数量凑验收。
6. 钱/鉴权/隔离/数据安全等影响较大的改动，查信任/事务边界及相关失败、重试、授权、并发、幂等路径。变异测试能有效验证断言时再做，隔离并恢复变异，留下恢复证据；不是每个功能都有上述全部行为。
7. 发现写位置、触发条件、实际/预期行为和证据。没实测的问题标未验证，不能写成已复现。范围外发现另立卡或形成明确决定。

## 把证据绑定到成果

结构化任务通过运行时 evidence 协议登记验收。不可覆盖的回执标明任务／spec revision、要求摘要、相关内容指纹、来源验证 attempt 或明确声明的人工来源、结论，以及需要时的审查者声明；包含实际证据文件与摘要。后续意见不能覆盖旧回执。

成功验证只能用于它真正检查过的要求和内容。运行时记录验证前后相关内容；后来代码或相关未提交内容变化，旧结果就不能直接沿用。纯 mtime 变化不等于内容变化。检查指纹范围：它不证明遗漏文件、ignored 输出或未测行为已覆盖。文件缺失、被修改的证据，以及旧版只有备注的验收，仍明确待核对。与任务要求无关的配置变化不自动使所有任务验收失效。

低影响任务可以使用适当人工审查，但要按实际内容登记为人工证据，不能冒充已运行测试。要求独立审查时，记录参与者与实现者关系，关联同一成果。合作身份声明不等于密码学身份，也不证明模型判断必然独立。

## 结论与独立性

- **通过**：记录验收为何覆盖本卡、还有哪些未验证；有证据才把任务标 `verified`。
- **修完再审**：按模板写有边界的意见，检查现场后继续已有工作。
- **调整方向**：解释失败假设，保护已有成果，只在策略和用户授权内调整范围/员工/设置。

总指挥可以实施任务卡。对较多自写实现、高影响改动或仍有疑问的部分，按项目策略做独立审查。给审查者规格与代码，不给自己的结论。它占 agent 槽位，需要获准派发路径。逐项复现/判断发现，不仅凭状态接受。项目要求独立审查但不可用时，报告该验收门未满足。

## 按项目策略整合

共享修改前确认当前 owner/epoch 和确切验收基线。使用 `guard --action merge`，遵守配置集成分支和合并方式。merge、squash、rebase、快进是项目选择，不存在全局 `--no-ff` 要求，也不以审查者偏好替换。非 Git 记录串行文件整合和本地快照，不做 Git 操作。

获准整合前，为选定任务／证据和实际目标基线建立结构化 integration 记录。实际整合后，对组合结果跑必要受影响检查，用对应验证完成记录。耗时验证在共享修改锁外运行，最终登记时在锁内重新核对目标与证据。结果提交或非 Git 内容必须对应真正测过的对象；验证后目标又前进，不能直接沿用旧的通过结论。

已经合并的代码与整体验收分开记录。A、B 单独通过但组合失败时，保留实际整合与失败证据，再按范围修复；不自动 reset，也不把组合标通过。允许批量整合后验证最终结果，避免每合一张卡机械重跑全套。成员／来源声明保持明确：摘要和通过测试不能证明任意合并命令包含每项语义修改。squash／rebase 无法证明的部分保留缺口。任务标 integrated 时须有适用的整合证据。

仍是 owner 时根据真实证据更新看板、任务索引、交接和相关决定，获准才提交。权限与节奏都允许才推送；本地成功和已记录的未推提交可以是正常结果。push 不授权发布/部署。

清理独立于验收。遵循保留策略，检查 dirty、未跟踪、ignored、未合并、运行中、未知和承载证据的成果。安全时才走受管清理。squash 结果无法证明已整合时保留 worktree 核对，旧 force 不能豁免检查。

## 返工单

使用 `templates/review.md` 记录结论、审查基线/配置 revision、真实命令/结果、必须修的复现、未验证疑点、获准范围和跳过检查。审查单可以收窄单卡，不能授予新权限或覆盖项目策略。遵守配置重试限额，换任务 ID 不会让重复失败消失。
