# `.orchestrator/`：换总指挥的文件约定

总指挥会换人：额度耗尽、换模型、换工具、换人。文件写得好，交接就是几分钟的事；写不好，下一个总指挥要从头查一遍。

## 目录

```text
.orchestrator/
├── PLAYBOOK.md      # 本项目的总指挥手册（角色、通道、模型推荐、锁、热点文件）
├── TEAM.md          # 当前 holder、拍板人、执行者花名册、授权
└── <agent>          # 可选：一条「接任申请」分支名或便签（未合并 = 待接任）
```

## `TEAM.md`

最小内容：

```markdown
# 团队

- 拍板人：<称呼>
- 当前总指挥（holder）：<agent 名称> · 上任 <YYYY-MM-DD> · 状态：在任 / 交接中 / 代理
- 上一任：<agent 名称>（<YYYY-MM-DD> 交棒给 <新 holder>）
- 临时代理：<agent 名称>（<起止日期>，只维持不扩张）

## 执行者花名册

| 名称 | 启动通道 | 默认模型 | 沙箱 | 擅长 | 已知坑 |
|---|---|---|---|---|---|
| codex | dispatch.sh codex | 执行者默认 | workspace-write | 仓库重构、跑测试 | 受限沙箱要放行主仓 .git |
| claude | dispatch.sh claude | 当前会话模型 | 由 --permission-mode 决定 | 长上下文、审查 | 默认交互式，无人值守要 -p |
| hermes | dispatch.sh hermes | 执行者默认 | 单发自动放行 | 真机、provider | 碰到 sudo 密码会退出 |
| dsh | dispatch.sh dsh | DSH 配置 | headless | 中文材料、调研 | `-m` 要写 provider/model |

## 派发通道

- <这个总指挥实际可用的方式：dispatch.sh / 子代理 / 人工转派 / 群聊>
- 派发前预检：`scripts/dispatch.sh <执行者> <worktree> --precheck`
- 日志目录：<路径>

## 授权

- 能直接派：<谁>
- 能推：<精确命令，或「只有拍板人能推」>
- 需要拍板人做的：<提权、外部账号、不可逆操作>
```

规则：

- **只有拍板人能改 holder**。
- 总指挥可以写自己的接任记录，但不能把 holder 改成自己（除非拍板人已任命）。
- 每次换人，新旧 holder 各写一段，**追加**，不覆盖。
- 执行者开工前看这里，知道回报给谁。

## `PLAYBOOK.md`

把本 skill 的方法**实例化**到本项目：哪些角色、派给谁、用什么模型、哪些共享资源要锁、哪些文件是热点。它是给「下一个总指挥」看的第一手材料，不是本 skill 的副本。

建议小节：

1. 角色与 holder（指向 TEAM.md）
2. 派发通道与预检
3. 模型推荐（本项目高风险卡用什么、普通卡用什么）
4. 共享资源与锁（端口、常驻服务、真机、凭据目录）
5. 热点文件与迁移规则
6. 本项目的额外红线

## 交棒检查清单（旧总指挥）

- [ ] `HANDOFF.md` 有「交棒给 <新 holder>」一节
- [ ] 进行中 / 待审的卡：分支、最后提交、还差什么
- [ ] 未推提交、共享资源锁 owner、还在跑的后台进程
- [ ] `questions.md` 未答事项
- [ ] **只在你脑子里的东西**：坑、没写卡的发现、执行者脾气、下一步该派什么
- [ ] agent 私有记忆里项目相关的条目，已抄进 `docs/plan/notes/`
- [ ] `TEAM.md` holder 已改，状态「交接中」
- [ ] 提交并推送

## 接手检查清单（新总指挥）

- [ ] 按顺序读：AGENTS.md → HANDOFF.md → status.md → questions.md → WORKER.md → TEAM.md
- [ ] 核实现场：`git status -sb`、`scripts/wt.sh ls`、进行中卡的分支提交、派发日志、进程
- [ ] 还文档欠账（看板与现实对不上，先修看板）
- [ ] 核对自己的能力，写进 TEAM.md
- [ ] 认领：TEAM.md 记「已接手」，状态「在任」
- [ ] 给拍板人一段话的接手报告
- [ ] 不重议已答的拍板

## 防止两个总指挥

- 以 `TEAM.md` 记录的 holder 为准。
- 未被记录的一方立刻降级为执行者：停写共享文档、停合并，按 worker 回报格式交活。
- 不许「改一下 TEAM.md」抢位——那是拍板人的权力。
- 发现 `.orchestrator/` 有未合并分支或 holder 是别人：报告，不自作主张接管。
