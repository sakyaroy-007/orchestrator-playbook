# 有边界的任务卡

使用 `templates/task-card.md` 或 `templates/spike-card.md`。项目可保留模板快照，配置路径与[配置参考](configuration.zh.md)优先。单卡收窄范围和权限，不能任命 owner、批准新员工、授予 Git 权限、突破红线或修改项目策略。

## 按契约拆

一张卡产出下一张消费的契约：函数签名、schema、端点或文件格式。上游整合前，下游使用明确商定的契约/mock，或写明依赖和确切起点分支，不能把未合并承诺当成已实现行为。

卡要小到能独立审查。建议 S（半天）、M（约一天）、L（约两天），更大就拆并预设拆分点。钱/鉴权/隔离与无关页面或重构分开。适合时按 Epic 编号，spike 用 S-NN。范围外发现开新卡，链接来源。

保留一行一项待办，只展开下一就绪波次。派发前按当前路径、契约和基线复核旧卡，旧行号不证明当前行为。有真实阻塞才安排地基波次。

## 卡片内容

| 字段 | 必填信息 |
|---|---|
| 派发口令 | 读员工规则和这一张卡，明确工作目录/分支，按模板回报；附加限制只能收紧 |
| 策略 | 配置路径/revision、决定证据、获准员工 ID；未定设置/权限阻塞对应动作 |
| 基线 | HEAD/分支或非 Git 快照，dirty/未跟踪事实，相关既有失败 |
| 目标与背景 | 可验收结果、实测动因，带命令/输出或文件证据 |
| 必读与契约 | 具体文件、ADR 小节及外部消费的名称/行为 |
| 范围 | 允许文件/操作、明确排除项、共享资源预留 |
| 依赖 | 必需的整合提交/契约，或已记录的上游起点分支 |
| 验收 | 可直接运行命令、cwd、预期外部行为、必须抓到的失败及覆盖限制 |
| 回报 | 实际命令/退出码/输出、覆盖范围、缺口、保留成果、范围外发现 |

真实派发口令使用项目解析后的绝对路径，避免员工猜 cwd。公开模板只留可移植占位符。不能在范围内完成时回报 `blocked`，附证据和推荐，不能自行授予例外。

## 登记可执行任务契约

新卡派发前完成并登记结构化 spec，记录要求／验收、相关内容的项目相对路径、上游任务／证据引用及仅契约或要求真实集成的模式、独占资源名称和必要审查声明。运行时保存要求 revision／摘要，保留旧记录。机器字段与人读卡片要一致；草稿或未登记的 Markdown 承诺不构成就绪条件。

对实际准备使用的工作树查询只读 readiness。它指出缺失依赖或资源占用；run 在同一预留锁内重新检查后才启动。要求真实整合的上游必须出现在消费者的实际起点，不能只写在备注里。明确允许的 contract-only 工作固定上游 spec revision／摘要，不要求其实现已集成，也不声称代码已验收。上游成果变化时，先核对下游验收／集成的适用性。contract-only 绑定 spec；integrated 依赖绑定完整的历史验收结果，并检查消费者实际基线。上游目标正常前进不会抹掉历史；发布变化后的目标仍须有绑定当前 HEAD／分支与范围的组合验收。

独占名称在整个项目跨 worktree 共用，例如 `port:3000`、`database:integration`、`file:package-lock.json`。热点文件明确声明单写者；字面范围相同与否不能代替语义资源规划。active／unknown 占用在执行真正结束或被明确核对前保留。readiness 不授予派发权，资源声明也不授予访问权限。仍由总指挥选择就绪卡，不意味着自动调度、rebase 或重试。

## 验收检查行为

- 定义可观察成功和有意义的失败路径，检查契约被破坏的情况，不只照抄实现输出或机械数断言。
- 保留已有测试意图，解释每项变更/删除的期望，不靠 skip、宽松比较或复制真实输出藏失败。
- 涉及共享状态、隔离或顺序时，加入相关单跑/逆序/随机检查，不要求所有卡所有测试所有顺序全跑。
- 钱/鉴权/数据安全按相关行为检查：授权、重试/幂等、部分失败、并发、持久化。审查深度与定向变异按影响和策略。
- 文档/调研验收核查结论准确、来源日期、引用和步骤可用。没依据的标未验证，小节数量不算证明。
- 卡里的预期输出与报告里的实际输出分开，记录基线/dirty，让后来结果可复现。

## 隔离与保护

Git 并行通常一卡一 worktree/分支，通过受管路径创建；非 Git 串行，明确目录并用本地快照。总指挥可以实施卡片，影响/策略要求时安排独立审查。

热点文件同一时刻一个写者，在看板和卡上预留。worktree 不隔离端口、服务、数据库或凭据。记录具体共享资源和协调机制，不能凭锁年龄认定空闲。迁移编号和 head 拓扑遵循项目契约，不设通用每卡一 revision 规则。

共享资源卡逐项列出已获准操作、备份/恢复证据和还原检查。单卡不能扩权。还原验证通过且保留策略允许后才清理备份。交互/特权步骤由具备相应授权的操作者处理，不自动改权限。

## Spike 与上游分支

Spike 在限时与明确操作内回答影响架构的问题。产出发现、实测证据、与实测分开的引用证据、限制、建议和恢复事实；未跑实验标未验证。未另列范围时不改产品代码。已接受结论回填决定，后续工作立卡。

基于未合并分支时写明确切起点与依赖；整合前与上游最终结果核对，并复跑受影响验收。不能静默 reset 或丢掉下游成果。
