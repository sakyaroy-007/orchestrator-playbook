## 项目决定

1. 所有权由共享运行时具体 session/epoch 记录，TEAM.md 仅作摘要。用户 start 无人占任时任命当前会话；resume 不夺权，takeover 按已准备交接/明确恢复。
2. Git 集成分支建议 `{{MAIN}}`，实际分支、merge_method、push_cadence、cleanup_mode 以 config.git 为准；权限分别记录于 config.permissions。没有固定 no-ff、强制推送或合并即清理要求。
3. Git 并行一般一卡一 worktree/分支，建议目录 `{{WT_BASE}}/<卡号>`，经受管路径创建。非 Git 串行并留本地恢复快照，不做 Git 操作。
4. 并发、重型任务、超时和尝试数用 config.limits；审查员工也计 agent 槽位。reserved/running/unknown 先核对，不盲目重启。
5. 共享文档明确写者，单卡限定文件范围，不能扩权。总指挥可实施合适卡片，按 review 策略与影响安排验收和独立审查。
6. worktree 不隔离端口、数据、服务或凭据；共享资源预留见看板/WORKER.md。迁移规则按项目契约：【待填】。
7. 保护 dirty、未跟踪、ignored、未合并、运行中、未知及承载证据成果。保留策略和整合证明限制清理；旧 force 不绕过，squash 无法证明时保留。
